# Waffle EDA 0.7.0 · Apricot Preview

Apricot Preview opens and saves native 2.0 project folders. It includes source EDA import, project hierarchy, infinite schematic sheets, connection navigation and active-document saves. Notebook tools are available under **Preferences → Experimental features → Enable notebook features**, off by default. For a first review, use a copy of a familiar routed design and keep its manufacturing outputs for comparison. The source checkout includes the public PiDP-11 I/O Expander in `tests/fixtures/altium`.

## Install and run

- **macOS 12 or later, Apple silicon or Intel.** Open the disk image and drag **Waffle** to **Applications**. Follow **Read Me First** on the image for the first launch. The app is ad hoc signed. Starting with macOS 15, open the app once, select **Done** when macOS blocks it, then choose **Open Anyway** in **System Settings → Privacy & Security** and confirm. On macOS 12–14, Control-click Waffle in Applications, choose **Open**, and confirm.
- **Windows 10 (1903+) or 11, x64 or Arm64.** Extract the Windows ZIP to a folder and run `Waffle.exe` from that folder. The portable app uses .NET Framework 4.8 and Microsoft Edge WebView2 Runtime. Keep the `app` and `runtimes` folders alongside the executable.
- **Debian or Ubuntu.** Install the `waffle-eda` package with `sudo apt install ./waffle-eda_0.7.0_all.deb`. Start **Waffle EDA** from the menu or run `waffle` in a terminal. The package also installs `waffle-mcp`. It uses Python, GTK 3 and WebKitGTK 2.42 or later.

Run `shasum -a 256 -c SHA256SUMS` on macOS or `sha256sum -c SHA256SUMS` on Linux from the preview folder to check the downloads. On Windows, use `Get-FileHash -Algorithm SHA256` on the ZIP and compare with its entry in the same list.

## What to look for

- **Start in Welcome.** On first run, choose a background under **Coming from** or start with a template. On later visits, filter **Recent projects** or use **All templates…**. The sidebar offers **New Project…**, **Open…**, **Try the Demo** and **Recover Unsaved Work…** when available.
- **Personalise the editor while you work.** **File → Preferences…** opens 14 searchable built-in pages in a modeless window. Settings apply as you change them. Close it with the titlebar button or press **Esc** while it has focus. **Restore Defaults…** asks before resetting the current page. **Window → Panels** controls panel visibility and **View → Theme** opens appearance choices.
- **Open an Altium, KiCad, Autodesk EAGLE or EasyEDA design.** Both EasyEDA Standard and Pro are supported. Open leaves the original in place. A quiet **Imported from…** banner below the document tabs offers **Save as Waffle Project…**. On first **⌘S** or **Ctrl+S**, **Enter** accepts the native project and **Esc** cancels and returns focus to the editor. Waffle then asks where to create the project folder. It starts beside your last Waffle project, or else next to the source project folder, so your Altium or KiCad folder stays unchanged unless you choose it. Cancel leaves the design open and unsaved.
- **Export in the source format.** Review the **Kept**, **Converted** and **Lost** features used in this design, then choose a separate destination. Select **Remember for this project** to reuse that destination on later Saves. **Save As** reopens the choice. For an unsaved import, **Keep for Later** on quit and **Restore Draft** recover the edit and source identity. Waffle can ask you to reselect the original or the destination when its previous permission is unavailable.
- **Review a foreign export.** The first-save sheet explains how Waffle preserves the original files. Choose **Export** to see what the writer keeps, converts and loses. Each listed reason belongs to the object kind beside it. A footprint graphic omitted on an unsupported layer appears under **Lost**.
- **Save and share a project folder.** Open a native 2.0 folder or its `.waffle` manifest. Edit a net label, save, and inspect the changed line in the sheet’s `.wsch` file. Use a portable project ZIP to share the complete saved design and its referenced inputs. Opening the ZIP creates a separate folder.
- **Trace a connection across sheets.** Hover over a schematic port, off-sheet connector or net label to see its destinations. Select a destination to open that sheet. Use **Projects** to inspect the project’s connection scope when reviewing an imported design.
- **Search and run a command.** Open the palette from the app bar, with **F1**, or with **⌘⇧P** on Mac. Type a command such as “reset view rotation”. The row shows its menu location. Waffle’s Mac desktop app uses the system’s Return and modifier symbols in the palette and shortcut recorder. Desktop rows are compact, and touch rows retain 44 px targets. **⌘K** on Mac, **Ctrl+K** on Windows and Linux, or **Actions** on touch opens its other actions. With notebook features enabled, **/** uses the same panel to insert an item.
- **Try the notebook in Experimental features.** Turn on **Enable notebook features**, open a sheet and press **/** to insert text, a calculation or an image. Save the sheet and reopen it. A newly attached image and its owning sheet save together. Turn notebook features off again to check how the saved design opens. **Place → Review Notes** opens the sheet’s controls for sticky notes, callouts, checklists and sketches. **File → Print…** includes Smart PDF options for links, bookmarks, viewer layers and the Notes layer.

1. **Open an Altium project.** Choose the `.PrjPcb` so Waffle can find its sheets, board and libraries. Inspect the import report and open every sheet. On the PCB, compare an arc, polygon or rounded pad with the original. Open 3D view, save the Waffle project, and reopen its manifest to check the same objects.
2. **Review a real change in Git.** In a desktop checkout, open the original tracked design and choose **Project → Git → Project History**. Open a rename or merge and check the before and after thumbnails. Compare the working copy with HEAD after a small unsaved edit, then undo and confirm that change disappears. On a changed object, use **Who Changed This?** and check the attributed commit. For a concrete comparison, compare the public Corne Cherry hotswap board at `c5d5a3d9` and `ffca3be3`. Look for one board-wide translation alongside individual routing changes.
3. **Update the PCB from the schematic.** Make a designator change and a footprint replacement on a copy. Choose **Design → Update PCB Document…** and inspect the component matches and Engineering Change Order. Check the footprint, designator, connected nets and retained routing after **Execute Changes**, then undo and compare again.
4. **Check the fabrication files.** Run ERC and DRC and inspect the markers. Then use **File → Fabrication Outputs…** to compare copper, solder mask, silkscreen, drill drawing and profile with the original. Check plating and slot geometry in the NC drill files. Review the physical alignment in a separate Gerber or mechanical viewer.
5. **Check a calculation in context.** Open **Tools → Calculators**. Select a PCB track to see resistance and current capacity, or an impedance-controlled net to check its layer, target and width. On the PiDP-11 schematic, select R4 and C2 together to see about 128.7 ns and 1.237 MHz. **Pin** holds the calculation and its inputs while you change selection. On a controlled-impedance design, review an offered adjustment with **Apply**, then undo it in one step.
6. **Route from the Nets panel.** On a copy with an unrouted differential pair, select one member in **Nets**, click **Route** and choose the highlighted source pad. To route several nets together, press **P**, then **M**, with the Altium keymap. Choose the bus net class, click **Start** and click near its source. Cycle to **Hug** with **Shift+R** and check copper spacing around an obstacle after committing. Also try switching to **Measure** during a component move and check that the dragged geometry returns to its starting position.
7. **Browse a folder library.** Open **Window → Library**, then **Add library folder…** from the source menu. Search before opening a result, then select a package to see its symbol and footprint. Press **Enter** to place it or use **Check…** to validate real geometry. Rescanning an unchanged linked folder should offer no component updates.
8. **Save and reopen.** Make a reversible edit, save, close and reopen the project. Repeat with an unsaved change and try each choice in the close prompt. To test live updates, join a local session in a second editor window. In the two windows, move different vias, then use Undo and Redo in the first window. Both windows should show the resulting copper and the second user's edit together.
9. **Review the exact AI proposal.** On a test copy with an unnumbered resistor and R1 available, ask the assistant to propose annotation. Confirm the card proposes R1. Give R1 to a different resistor before you click **Review proposal**. The card should say the proposal is stale. Request a fresh proposal, review it and use **Apply selected**. Undo should remove that one accepted edit.

With a saved `.waffle-ai` file beside your project, MCP clients can inspect it using `apply_proposal` in plan mode. New connection setups start in **Read only**. For a write test on a saved copy, use `--allow-write` and `mode: "write"`, and pass the returned `proposal_sha256` and `source_sha256` to apply the exact file you inspected.

## Verification and known issues

- **History.** The tests covered 1,042 first-parent comparisons across eight original-format designs. The 117 manually checked rows agreed on whether the selected design or project settings changed. Check object matches individually on heavily rearranged boards and on older KiCad copper that lacks unique object IDs. A repository with drawings stored only inside ZIPs needs an individually tracked drawing to use this workflow.
- **Native Save.** In timing build `d729c818` on an Apple M6 Mac, all 60 first saves and 997 of 1,000 later saves met the 50 ms limit across ten designs. Every first and subsequent save must be strictly under 50 ms for formal Apricot.
- **Native Open.** On the same timing build, all 30 fresh opens reached editable geometry. Median time to editable geometry was 106 ms for PiDP-11, 193 ms for CM4–5 Shim and 247 ms for the 25,600-item PCB. Their formal Apricot limits are 65, 100 and 86 ms respectively.
- **Command search.** On the same build with notebook features enabled, the first selected row took 68.20 ms at p95 in Chromium and 91.66 ms in the Mac WKWebView host with 50,000 library entries. Indexed typing took 19.48 and 28.35 ms at p95 respectively. The target is two refreshes (33.3 ms at 60 Hz, 16.7 ms at 120 Hz) for opening and typing, at most 8 ms of Waffle work per input, and zero samples beyond three refreshes. Physical display timing, end-to-end Waffle work and 120 Hz still need verification.
- **macOS.** Programmatic tests exercised the native WKWebView editor and folder saves. Packaging checks cover both processor slices, ad hoc signatures and files inside the mounted image. Physical 120 Hz, touch and pen input still need a hardware run.
- **Linux.** An earlier internal QA package ran the real GTK/WebKitGTK app on Ubuntu 24.04 arm64 under Xvfb. All eight native checks and 43 applicable display and input checks passed, including cancelling a wire drag. Two isolated containers joined a live session by address and code and exchanged an edit. Physical LAN discovery still needs verification.
- **Windows interactive/pen unverified.** The Windows package includes x64 and Arm64 loaders. Cross-builds and portable core tests ran on macOS. Native WebView2 launch, keyboard, touch and pen input, system dialogs and NTFS recovery still need a Windows hardware run.
- **CI artifacts.** Two GitHub-hosted jobs uploaded and downloaded a synthetic file. A separate download matched both the archive and file checksums. The preview installers are distributed locally.
- **Altium fabrication.** Across six public projects, none of the 62 previously comparable Gerber layers moved further from the shipped artwork. Measurable differences remain, including legend artwork, mask and copper. Some source rules still appear as original text in the import report and need interpretation. ODB++ remains unsupported.
- **3D and interchange.** Altium Designer 26 opened Waffle’s exported PiDP-11 schematic with the original counts of 23 components, 69 wires, 52 net labels and 22 power ports. The original binary PCB displays populated packages in both editors. An ASCII PCB can reopen in Altium with empty bodies even when the ZIP contains the STEP files. Use a source-preserving copy for supported edits to an existing Altium design, and inspect the 3D view before exchanging it. [Altium import and export](importing.md)
- **Library and collaboration.** Browser-only folders can need reselection after restart to open their geometry. Keep an independent copy for shared-folder takeover and long offline sessions. Check schematic connectivity and PCB pad assignments after a library update. Run board checks and examine the plotted files after routing and before fabrication.

## Your files and feedback

**Keep or copy the whole project folder**, including the `.waffle` manifest, sheets, boards, libraries, models, `assets/` and the hidden `.waffle/` directory when present. The manifest alone contains only part of the project. For a design from Waffle 1.x, re-import its original EDA project, such as the Altium or KiCad source.

**Browser saves.** Browsers with writable file handles can remember the destination. A permission that identifies only the current import is labelled **Remember while this import is open**. A download-only browser offers a separate file or ZIP and asks again on the next Save.

**Welcome → Recover Unsaved Work…** and **File → Recover…** list local recovery snapshots. Welcome progress belongs to your app profile. Recent lists can reveal project names and paths, and recovery screens can show unsaved designs. Review screenshots and settings exports for private information before sharing them.

A native folder may also contain a temporary save journal in `.waffle/journal/` while installation completes. Reopen the folder to let the editor finish recovery or show any conflict.

When reporting a problem, include the version from **Help → About**, your operating system, the project type and approximate size, and the steps that produced the result. Include the relevant comparison, report or screenshot when safe to share. Use a small public example or remove private design details. If you experience a lost edit, mention whether **File → Recover…** offered it and whether the editor showed a conflict or recovery message on reopening.
