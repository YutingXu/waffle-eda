# Waffle EDA native project format 2.0

**Native 2.0 with the durable-document amendment.** A Waffle project is a folder. The `.waffle` manifest names its documents and holds shared design records. Each PCB, schematic, component definition, drawing and panel is one regular file. A component move or net-label edit replaces one line in its owner. A new track adds one line. Saving that document leaves the manifest alone. Waffle acknowledges **Saved** when the complete new bytes and their transaction descriptor are durable. It then installs those bytes in the working folder. Save, autosave and recovery are local filesystem operations.

The development build used for the historical measurements wrote **1.5**. These measurements are a historical baseline. Public Waffle projects start with native format 2.0. The never-break-data commitment starts with the first public 2.0 format. The specification covers native folders, saving and recovery, import sidecars, ZIP export and Git ignores.

## Project contents

```text
Sensor Board/
  Sensor Board.waffle
  Power.wsch
  Main.wpcb
  libraries/
  models/
  .waffle/
    .gitignore
    imports/
    cache/  previews/  history/  journal/  local/
```

| Owner | Persistent contents |
|---|---|
| `.waffle` manifest | A `project` header with project ID, name and optional authored entry-document ID. One `document` reference per sheet, PCB, drawing or panel gives its ID, `docKind`, filename stem as its name, and relative path. A document reference contains no content digest. Rules, signals and tags, variants, shared settings, project waivers, BOM views, output jobs and other shared entities have individual ID-bearing records. File-backed definitions and assets are referenced here or through a typed owner. |
| `.wsch`, `.wpcb` | One `schematic` or `pcb` header with the document ID. The document owns its geometry, items and document settings. Sheet symbols and hierarchical ports reference stable sheet and port IDs. A repeated channel is an instance of a sheet. |
| `.wdraw`, `.wpanel` | The existing drawing and panel document kinds have independent files. Views, dimensions, cell transforms and repeats reference the live board, sheet, anchor or frozen revision by ID. A drawing stays printable and a panel stays editable after a round trip. |
| `libraries/` | One native `.wlib` per addressable component definition, with a `library` header, pins, pads, shapes, symbol gates and footprint data. The manifest indexes its stable ID and path. Family membership, stable library revision references, local overrides, pin maps and provenance of an authored library revision survive. A layout block uses a `.wblock` file with its own ID scope for its copied items and definitions. Instantiating a block allocates new live IDs and rewrites links together. |
| `models/<sha256>.<ext>.gz` | One deterministic gzip file per distinct native model payload, named by the full lowercase SHA-256 of the **uncompressed** bytes and its canonical media extension. Display names, units, axes, placement, offset and aliases belong to references. An unresolved model keeps its named reference and placement and reports its missing payload. |
| `assets/<sha256>` (as needed) | Other durable native payloads, including images, exact project extension packages and immutable released design snapshots. A snapshot root pins historical document, library and asset digests, recursively including its model dependencies, independent of the mutable working paths. Release letter, notes, status and date are authored records in the manifest. Validate the whole snapshot when used. |
| `.waffle/imports/<source-sha256>/` | Committed bindings connect native IDs to original input records, translator/report versions, fidelity findings and exact residuals. The manifest names the index by stable ID and path. The binding records the original input digest, and either its same-repository commit/path or its copied bytes. Repeated references share one source. |
| `.waffle/local/` | Per-profile last-saved document hashes, open tabs, active document, layout, camera, grid display, selected objects, active viewing variant and recent queries. Shared manufacturing variant choices belong to the authored output job. Cache, preview, private undo/history, autosave and transaction records each use their own ignored store. |

The suffix and first-line kind must agree. A PCB is `.wpcb` / `pcb`, a schematic is `.wsch` / `schematic`, a component definition is `.wlib` / `library`, a drawing is `.wdraw` / `drawing`, and a panel is `.wpanel` / `panel`. Each path is a single regular file. Refuse a directory with one of these suffixes, a link or reparse point, or a manifest reference that uses a document path as a directory. A project folder can contain one or more of those files, plus the other separately typed owners and assets in the table.

Open a selected member as a file using the same header, row and version checks as a project member. Resolve design dependencies only in an explicitly opened project or separately selected scope. Waffle can open a member in its owning project if the containing project is resolved unambiguously and its manifest names the same member path, ID and kind. A loose file can expose its own content without creating a manifest on disk. A loose-file write is limited to the one granted path and checked against its saved byte digest. Changes that need several owners or a new dependency require an explicit project operation.

Keep native circles, lines, holes, pad-stack lands, ordered layers, rules, copper fills and 3D placements sufficient to render and manufacture the design after discarding import data. Verified imported copper that the native solver cannot reproduce stays as native contour or stroke geometry. A reproducible tessellation or search index may live in the cache. Raw Altium rule/class records, source drill indices, original aliases and lookup checksums, KiCad source syntax and vendor-specific field names belong to the bindings under `imports/`. A project extension's intentional simulation data, decimal values, schema version and signed package bytes survive under its own namespace. Installing, trusting or activating an extension is a separate local action.

A polygon with committed copper may carry `copperBasis`. Its `inputs` value identifies the native board geometry and applicable rules used for that polygon. Its `contours` value fingerprints the owner IDs and the exact ordered copper geometry, including a verified empty fill. Import establishes this record after verifying the source fill and projecting the board into native units. Explicit repour updates the affected polygons. A reader that cannot verify both values refills the affected copper for manufacturing. Reading a board, plotting it or inspecting a pour does not update this record.

After a failed refill, a writer can keep the last contours for display. It removes `copperBasis` from every affected polygon, including downstream pours whose result depended on the failure. This applies to full and incremental saves. A reader must obtain a verified refill before using those contours for manufacture.

Current writers can also record the affected polygon IDs in `documentSettings.value.pcbDrawing.pourUnverified` as an array of distinct nonempty strings. This lets a reader distinguish a failed empty result from a pour that has yet to run. Preserve a pre-existing value of another shape. When that name is occupied, a writer uses the first free name in the sequence `wafflePourUnverified`, `wafflePourUnverified1`, `wafflePourUnverified2` and onwards, with the value `{"format":"waffle.pour-unverified/1","owners":["<polygon-id>"]}`. Read this alternate form only when both the format and owner list are recognized. A successful refill clears the corresponding failure state. The missing certificate also protects earlier 2.0 readers, so this metadata adds no `requires` token.

## Rule scopes

The first Apricot build stores native query language version 1 in format **2.0**. Each manifest `rule` owns `value.scope` and its stable ID. Clearance, short-circuit, creepage, return-path via, parallel-segment and component-clearance rules also own a required `value.scope2`. Both sides keep their original roles. A single-scope rule omits the second side. Named rule-set templates use the same scope values. The ordinary manifest header contains `"formatVersion":"2.0"`.

The optional `value.presetKey` identifies a fabrication preset or rule-set slot so reapplying the same template can reuse the accepted rule. It is a string of up to 256 characters. Rules are still addressed by their record ID. Previews may use deterministic template keys internally. Accepting a new rule allocates its UUIDv7, and saving preserves that UUID in the record and its value.

```json
{"languageVersion":1,"source":"object in class \"HighSpeed\""}
```

`source` preserves the authored Unicode text, whitespace and units. `object` selects the eligible domain of the consuming check. An optional `bindings` array identifies authored reference occurrences with `id`, `name`, a half-open UTF-16 `span` and an optional typed stable `target`. Source offsets and target IDs are independent of the native geometry unit. A project parameter reference may carry `parameterId`. For `track where width < project.MinTrace`, the target `{"scope":"project","parameterId":"p-min","field":"mintrace"}` tracks the same parameter when its display name changes. A broken target stays bound to its original identity and produces a diagnostic. A scope-only change replaces the addressed rule row. Its order, opposite side and other project members retain their saved values. [Query language and binding contract](query-language.md)

Supported foreign predicates are translated before a rule is created. Retained source spelling, record locator, losses and raw foreign data belong to the import bindings and source sidecars. A future language version is carried explicitly through unrelated edits and leaves dependent checks incomplete until a reader supports it. Smart groups are planned for Butter. An ordinary rule works without a saved group or an extra required-feature header.

## Canonical records and dimensions

Each native text file is UTF-8 without a BOM. Its first physical line is the header. Read through the first LF within 65,536 bytes and check the header before decoding the rest of the file. Each subsequent physical line holds one complete JSON object. LF terminates every line, including the last. Empty lines, comments, trailing commas and duplicate decoded keys are invalid. Newly authored JSON emits keys `kind`, `formatVersion` and `id` first, in that order, wherever present. Sort remaining keys in unsigned UTF-8 byte order of their unescaped names. Write compact JSON with no separator whitespace. Encode quote and backslash as `\"` and `\\`. Encode U+0000–001F and U+2028/2029 as lowercase four-digit `\u` escapes. Write other Unicode scalars literally, including slash. Writer-authored strings cannot carry unpaired surrogates. Preserve user text as entered, including distinct combining sequences.

Every independently addressable entity has a nonempty opaque ID. Sort data lines by the unescaped ID's unsigned UTF-8 bytes. Keep valid, unique IDs from earlier Waffle files. Allocate new native identities as lowercase RFC 9562 UUIDv7 strings in the usual 8-4-4-4-12 form. UUIDv7 puts milliseconds since the Unix epoch in the most significant 48 bits, with version bits `0111`, variant bits `10` and a 74-bit remainder. Use secure entropy to seed the remainder and a monotonic generator within a writer so a repeated or regressing clock does not duplicate or reorder its new IDs. A move, rename, save, redraw or library refresh retains the ID. A copy gets a fresh ID, with internal references remapped once. Object, definition and document IDs in a live project are unique. A manifest reference and its matching file header name the same identity. Nested block and frozen-revision IDs are qualified by their owner. Duplicate or ambiguous identities are errors. A designator alone is insufficient to pair parts. [RFC 9562 §5.7 and §6.2](https://www.rfc-editor.org/rfc/rfc9562.html#section-5.7)

A model alias's lookup ID belongs to its owning document or definition. Writers qualify the native record ID with that owner and retain the local lookup ID for placements. Earlier 2.0 writers stored the local ID in both fields. Readers qualify those identities by owner without changing the saved bytes. The local lookup ID must be unique within each owner, and the earlier unqualified record ID cannot collide with another live object ID.

Physical line order carries no electrical, stack or drawing semantics. Use a persistent order key on the owner for meaningful ordering, such as a layer, draw order or a sheet's place in the navigator. Use Waffle's fractional base-62 order, compared by ASCII, with ID as the tie-breaker. Sequences internal to an entity, such as a contour's segments, wire vertices and ordered pin-pair paths, retain their element order. Individually addressable contours own their own records. An anonymous point sequence always stays on its owning record, regardless of length. Unordered membership uses individually keyed records or sorted unique values as specified by its field. Appending the benchmark track requires one new data line. Reading or showing a document must preserve the saved presence of optional fields. Required defaults are specified by kind, and fields with a defined implicit default take their canonical omitted form. An explicitly meaningful null, such as inheritance, stays distinct.

### Header and reader capabilities

The header carries `kind`, `formatVersion` and `id`. The version is `major.minor`, with decimal components from 0 through 9999, no leading zeros except `0` itself. A project header also carries a nonempty `name`. Every newly written 2.0 document or component-definition header declares `requires`, using an empty array when all its records are understood by baseline readers. A previously saved header may omit it, which is equivalent to an empty array. Keep the saved header when an ordinary edit changes only data rows.

`requires` contains unique, nonempty, case-sensitive feature tokens. Include a token only when ignoring its meaning would misrepresent the owner. `readerRequires` is an optional object whose keys are listed tokens and whose values use the native version syntax. It identifies the minimum native reader format when the producer knows it. Neither a newer minor nor a minimum version entry implies support for a token. A reader must recognize the token independently.

A 2.0 reader can open known content of a same-major owner with an unknown required token read-only. Report the exact token and the recorded minimum native reader format when present, or the file's actual declared format when absent. A project-header requirement makes the whole project read-only. A requirement on a document or definition protects that owner. A future major requires a declared supported subset, such as `"compatibleWith":"2.0"` for a 2.0 reader, plus a valid representation of that subset. The subset is read-only. Refuse an unsupported major without a supported subset. A live member must share its manifest's major and have a minor at most the manifest's minor. Frozen members keep their own versions.

`continuation-parts-v1` is reserved for a future format. A reader that sees this required token refuses the owner from the first line and reports the exact token and the declared format before reading or resolving its body. Format 2.0 defines no continuation syntax, part filenames, discovery rules or writer for that token. An ordinary 2.0 reader opens each known member from one regular file.

### Opaque fields and records

Keep the raw UTF-8 bytes beside the known projection. An unknown optional record needs a valid, nonempty `kind` and `id` and obeys the same ID ordering and uniqueness rules. Keep the whole line, including whitespace, escapes, member ordering and number lexemes. For unknown fields within a known record or header, including `x-*` extensions, keep the original key and value spans at their authored location and preserve their spelling and spacing. The same rules apply inside recognized arrays and objects. A future large integer or exponent in an opaque value is data to retain. A language's numeric conversion or JSON reserialization cannot serve as the only saved representation. An unknown row or field that the editor cannot represent remains out of the editable projection. A known enclosing structure may be edited only where the writer can preserve the opaque data. Refuse a change that would drop it, move it ambiguously or make an unsupported owner writable. Reject invalid JSON, duplicate decoded keys, malformed identities and malformed known fields even when other fields are opaque.

Use the published Draft 2020-12 JSON Schema for row shapes. Validate the first line with `#/$defs/header`. Use `#/$defs/amendedOwnerHeader` to check new document and component-definition output and the matching owner record definition for a recognized body row. Apply `opaqueHeader` or `opaqueRecord` only under the capability rules above. File-level validation also checks exact encoding, lexical integer form, feature support, ID uniqueness and ordering, suffix and membership, and digest closure. A structurally invalid known row cannot pass via the opaque schema. [Native record schema](../integrations/vscode/schema/waffle-folder-record.schema.json)

New native text files use LF. Readers may normalize LF/CRLF transport when computing logical digests. Physical writes preserve untouched lines including their original delimiters, even in a mixed file. An edited row keeps its delimiter, and a new row uses the saved owner's header delimiter. Every byte within an opaque JSON line or retained value span remains significant. Journal target checks use the exact physical bytes on disk, including each CRLF. Preserve intentional dates such as a release or waiver creation date. Clock times of a save, transaction identifiers and last-saved hashes stay in ignored local state.

### The computed project version

Desktop, MCP `source_sha256`, History, collaboration and project-level caches use the following single definition. Let `manifest` be its complete canonical UTF-8 bytes. Enumerate the transitive closure of authored members starting from manifest records, including live documents, library definitions and blocks, reachable frozen records, models, native assets, and retained import indexes, reports, bindings and original inputs. Resolve each logical root-relative path once. Exclude the manifest itself from the member list, unreferenced files, Git data, the five ignored stores and `.waffle/.gitignore`. A cycle in an asset graph cannot duplicate a path. A missing required member, path collision or inconsistent content identity makes the full version unavailable.

For retained source bytes, reserve `.waffle/imports/<source-sha256>/source` as the logical member path irrespective of whether the bytes come from a verified Git blob or a copied file. The repo-relative file is a locator and does not enter the closure a second time. A binding's explicit path, commit and source digest are themselves authored provenance. For native text the member digest is SHA-256 of canonical bytes. For binary assets, exact source bytes and signed packages it is SHA-256 of the raw stream. For a model member it is SHA-256 of the canonical gzip file. Verify the decompressed bytes against the model identity in its filename as a separate check.

Hash the following byte sequence with SHA-256. `u32` and `u64` denote unsigned big-endian integers. Digest fields are exactly 32 binary bytes. Path lengths count UTF-8 bytes and paths use the normalized portable spelling defined below.

1. ASCII `WAFFLE-PROJECT-V1`, one zero byte, `u64(manifest length)`, then the manifest itself.
2. `u64(member count)`, then one entry per member, sorted by unsigned UTF-8 bytes of its full logical path.
3. For each entry append `u32(path length)`, path bytes and the member digest. No separators or trailing bytes follow. Report the final hash as 64 lowercase hex digits.

For the example, the sheet's SHA-256 is `97ff75921360fc03cc25687c26d8635d8ab222241d0fa2cfe1af94e8f2300e7c`. Its path is 10 UTF-8 bytes. The 240-byte framed input produces project version `0b1e6a5e9b241a9ffb2f1fd92fbafb656d1cd6f3f64e908c7c591d55c8135f64`. A one-line edit changes this version without touching the 160-byte manifest. Renaming a member changes its path and the manifest membership row.

**Lazy verification.** Keep a private index of path, last-saved canonical and physical hashes, verified dependencies and filesystem identity under `.waffle/local/`. An ordinary Open only needs the manifest, its selected document and visible dependencies. A Ctrl+S updates the local hash-index entries for touched paths. Neither operation waits for a complete project digest. A caller requiring the complete version requests it explicitly in a worker. Under the read barrier, reuse verified entries from immutable Git blobs or a reliable file/change token, and rehash new, changed or uncertain members. A timestamp and size alone do not prove equality. On watcher overflow or an interrupted cache update, invalidate uncertain entries. If a snapshot changes during a read, retry from a coherent view or report a conflict. A scoped command can return the document identity immediately and indicate a pending full revision when its contract permits. A whole-project write precondition needs the verified complete digest. A history commit uses only files and bindings at that revision.

Goldens must verify this framing on all hosts, with a non-ASCII path, duplicates rejected, CRLF checkout, reordered membership, a changed member with an unchanged manifest, a different basename, local-state churn, a missing member, and ZIP extraction without a repository. Trace bytes and paths opened on a cold visible-only read, a cold full-version request and a warm request following a single edit. The cold full request can read the entire closure. A valid warm index rereads only uncertain/changed bytes. The sorted digest list still costs O(number of members) when a new full aggregate must be computed.

### Stored model bytes

Version 2.0 uses a single gzip member per distinct native model payload. Lengths throughout the native schema are signed integer **nanometres**. This includes coordinates, origins, vertices and control points, pad lands, holes, offsets, board thicknesses, grid spacing, clearance and rule limits, view geometry, reusable definitions and 3D translations. One mm is 1,000,000 nm and one mil is 25,400 nm. Coordinates use +X right and +Y down on the sheet or flat PCB. Store only exact integers in the interoperable range ±9,007,199,254,740,991, retaining tighter per-field validity limits. Widen intermediate arithmetic where unit conversion would overflow that range. Quantize once, from the exact input quantity, to nearest integer with ties to even. Negative zero encodes as `0`. Render transforms are derived from the stored values. An untouched object is saved from its exact integers after any number of renders, edits elsewhere or undo cycles.

Angles use integer **nanodegrees**. One turn is 360,000,000,000. Normalize orientations to the half-open interval from zero to one turn. Positive 2D angles turn from +X toward −Y on screen. The legacy adapter converts clockwise placement angles and preserves the existing board arc convention. A centre/radius arc has `kind:"arc"`, `c` as a pair of nanometre coordinates, positive radius `r` in nanometres, `start` as an orientation and nonzero signed `sweep` in nanodegrees. For example, `{"kind":"arc","c":[1000000,2000000],"r":500000,"start":0,"sweep":90000000000}` ends at the upper cardinal point, [1,000,000 nm, 1,500,000 nm]. A full circle explicitly has sweep ±one turn. Finite arcs retain winding and a zero sweep cannot imply a circle. Bend sweeps keep their signed physical meaning. In 3D the board is right-handed with +Z up, X right and Y up. Apply X, Y then Z rotations about the defined model axes and retain bottom-side flip and placement order. Save the exact arc parameters. Display polylines are derived.

Counts, identifiers, flags, indices, ratios and electrical quantities have their own types. For a nonintegral scalar, the field schema fixes its unit, such as ohms or hertz, and uses an exact decimal string with optional minus, no exponent, no leading plus, no redundant leading or trailing zeros and no negative zero. Native JSON numeric tokens are integers. This keeps display units, script/model text, imported values and geometry on distinct conversion paths.

A source value of 2.54 nm becomes 3 nm with a residual of −0.46 nm. Record a nonzero residual as an exact rational and unit against the source reference, native ID, property and fingerprint of the translated value and relevant transforms. The report counts it as approximated. The native design is usable with the 3 nm value. A translator can reproduce the original precision while that binding matches. An edit invalidates the affected binding and export uses the edited native value. Report collapsed topology, a zero-width feature or an out-of-range quantity explicitly. Preserve its original input. Apply the same rules to nested geometry, rotation and rule limits.

New residuals also carry the original native record kind as `recordKind`, separate from the existing value fingerprint. Source-assisted export checks it against the current native record kind before restoring a value. For older residuals, use verified original-source evidence for the owner, kind and field. Export the current native value when that evidence is unavailable.

## Save scope and incremental work

**Ctrl+S** captures the active document's edit cursor and writes only that document on an ordinary edit. A document addition, removal, rename or move also changes membership and includes the manifest in the same transaction. A project-settings view writes the explicitly edited shared records. Compose any changed manifest from the saved baseline plus the selected authored changes. Other dirty documents and project settings keep their own pending edits. A clean Ctrl+S writes zero design files. On a new project, choose a new folder and establish membership on first save. When an active document first references a new immutable asset, stage the new bytes and the changed document in the same transaction. Install the verified asset before installing its owning document. A crash before commitment keeps the old document intact. Recovery after commitment installs both. A later ordinary edit to that document reuses the asset and writes only the document.

If the document requires a new independently authored library or an indivisible multi-document ECO, identify the dependency and offer **Save All**, preserving the scope of an ordinary Ctrl+S.

**Save All** captures all dirty document, library and project revisions, including structural changes and required new assets. Only changes actually authored in those owners are serialized. Clear the captured dirty revisions when the descriptor is durable. Edits made during I/O stay dirty. An error before commitment leaves all affected revisions dirty. A conflict during apply retains the committed staged bytes and marks the workspace **Saved, external conflict** until resolved. Released or read-only designs follow the existing copy/new-revision policy. Save As can establish a complete new folder.

At hydration or import finalization, retain each object's original line and delimiter, keyed by stable ID in an ordered document index. Seed it from **persisted authored bytes** before consumers may derive display or analysis data. Changes and Undo/Redo supply the inserted, updated and removed IDs plus their owners. Encode only those rows, splice into the ordered representation and retain an immutable cursor for the captured save. Use a segmented ordered index or equivalent structural sharing, so a splice never copies or shifts a whole document on the editor thread. The editor's work scales with affected rows and index lookups. Track cross-owner edits explicitly. Ordinary saving must never stringify, diff, clone or transfer every object in a document or project, including post-save, Undo and collaboration housekeeping. If a format upgrade or bulk operation really touches every object, declare it explicitly and report its wider cost.

**Incremental owner splices.** For an edit to an existing owner, locate changed rows by ID against the saved byte cursor. Send the owner's raw expected SHA-256 and a splice object `{base,edits}` whose `base` equals that hash. Each edit is `{offset,remove,insert}`. `offset` and `remove` are byte counts in the unchanged base, and `insert` is UTF-8 text containing whole physical rows and their delimiters. Insertions have `remove:0` and deletions have an empty insert. Sort by increasing offset, coalesce adjacent edits, and reject overlaps, out-of-range spans or an unexpected base hash. The file writer streams untouched byte ranges and new rows into staging to produce a complete target, verifying both the raw source hash and the new length and hash. Newly created or fully transformed owners can send complete bytes. Recovery reads the staged target independently of the splice and old bytes.

## Durable save and roll-forward recovery

One protocol serves macOS, Windows and Linux on **one machine**. Waffle writers, including MCP, share a stable OS-released exclusive project lock. Readers take the corresponding shared lock or check the active descriptor and a reliable local change epoch on both sides of their read and retry. If a valid descriptor exists, wait for apply or a recovery-capable host to finish it. A timed-out or read-only caller can report recovery pending. No editor, MCP query, History reader or ZIP exporter may expose a mixed project. The lock coordinates participating local processes. On network shares or volumes with unreliable locking, rename or flush, warn at save time and offer a local folder.

1. **Prepare.** Under the writer lock, finish any earlier active transaction, verify relevant membership and base hashes for the chosen edit, and check name collisions. Capture desired content in a fresh private `.waffle/journal/<transaction>/` under the bound root. Write the **full new bytes** for every created or modified path, including the new manifest only if it changes. A deletion needs only an expected current hash and desired absence. Flush all payloads, their directories and required new directory entries. At this point no authored working file has changed.
2. **Commit.** Atomically publish a checksummed `.waffle/journal/active` from a flushed temporary and flush its parent. The descriptor names the prepared transaction, project ID, and each target with its expected current raw SHA-256 or absence and desired raw SHA-256/length or absence. **The durable descriptor is the commit point and permits the Saved acknowledgement.** If a barrier fails or its outcome is uncertain, preserve the journal, recheck its state and report uncertainty rather than acknowledging an unverified commit.
3. **Apply immediately.** Keep the separately verified desired bytes in the transaction until every install and conflict is resolved. Use a fresh same-volume installation temporary for the full new bytes, flush it and rename it into place. A mutable working file must not alias the sole retained desired copy. Under the lock, obtain the current target's physical hash/absence and check its directory identity just before each replace or removal. For creation, require a no-replace install. Inspect an occupied name under the rules below. Flush affected files and directories. Verify every target's final state, then unlink `active` and flush its parent **before** cleaning up the transaction directory. Local hash-index updates can be rebuilt from the installed files after a crash.

The portable descriptor is ASCII `WAFFLE-TXN 1` plus LF, the lowercase SHA-256 of the following payload plus LF, then one compact UTF-8 JSON object plus LF. The checksum includes that final LF. Write fields in UTF-8 key order. The object has `plan`, `projectId` and `transaction`. `transaction` is a transaction UUID. Each ordered plan entry has `desired`, `expected` and `path`. `path` is the normalized relative target. `expected` is the raw SHA-256 or null for expected absence. `desired` is `{"length":N,"sha256":"…"}` or null for deletion. Within `.waffle/journal/<transaction>/`, store each complete desired payload under its lowercase digest. Validate descriptor version, identity, permitted target paths, operation count and lengths before reading bounded payloads. Hash-verify each staged file. A changed manifest is an ordinary plan member and can be installed after the data files. Its installation has no special recovery meaning.

**Loose document saves.** Use `.waffle/journal/member-<digest>/` beneath the granted parent, where the namespace digest is SHA-256 of the UTF-8 NFC basename with ASCII A–Z lowercased. Bind the lock, `active` and staged transaction directory to this namespace. The descriptor's `projectId` is the selected owner header ID. The plan has exactly one target, equal to the authoritative basename with its exact spelling. Both expected and desired digests are present. This scope allows only replacement of the selected regular file, with matching kind and ID. Apply the same prepare, publish, acknowledge and roll-forward rules. A link, unexpected replacement or different spelling cannot grant a new write target.

A filename change is a creation with staged full bytes and a removal of the old path, accompanied by its manifest edit. For a normal rename install the destination exclusively before removing the source. For a case-only rename on a case-insensitive volume, verify that the destination aliases exactly that source at preflight, plan removal of the original spelling followed by exclusive creation of the new spelling, then update membership. Compare the actual directory-entry spelling after NFC normalization, not an alias lookup that could delete the new name on replay. If a different entry occupies the requested spelling, stop in conflict. The plan's explicit order handles these dependencies identically on every replay.

| State on open or retry under the local writer lock | Action |
|---|---|
| Only uncommitted staging exists | Open the existing project. No working files were touched. Reclaim only known orphan transaction directories. |
| A valid descriptor exists and a target already equals its desired digest or desired absence | This operation has completed. Proceed to the next entry, including after a crash between rename and directory flush. Flush again before clearing the descriptor. |
| A valid descriptor exists and a target equals its expected digest or expected absence | Finish the operation from its complete staged bytes, or remove the verified expected file. This covers a crash after commitment, between any two installs, or before/after a manifest install. |
| A target holds neither expected nor desired state, or a creation meets an unexpected entry | Stop applying. Preserve the external contents, independent staged new bytes and descriptor. Identify affected paths. Offer merge, export staged bytes or keep the external version through an explicit conflict resolution. Readers wait or report the conflict. |
| Descriptor checksum/version, path or required staged bytes cannot be verified | Preserve evidence and report recovery unavailable or a compatible version required. Hold the reader barrier while the descriptor remains unresolved. |
| Every path is at its desired state and `active` remains | Flush the verified published namespace, remove and flush `active`, then clean up. Repeating recovery is harmless. |

When the user resolves an actual conflict, first preserve the competing versions for review. Under the same lock, atomically supersede the active descriptor with a flushed, explicitly approved full-content plan whose expectations match current disk states and whose desired bytes represent the agreed complete result. Already-applied paths are verified or included with their chosen final values. A crash on either side of descriptor replacement resumes whichever complete descriptor is durable. A delete conflict keeps the external file and the explicit deletion intent until this decision. A separately versioned private autosave draft names the document and its saved content hash. Offer a draft against a changed base as a separate recovery choice. Wall-clock ordering never decides which authored content wins.

Raw hashes detect equal-size and equal-timestamp external edits. Keep an observed unexpected target untouched and retain Waffle's staged version. A process that ignores the Waffle lock can change an existing target in the final check-to-rename interval on a filesystem without conditional replacement. Ordinary rename supplies no atomic hash compare-and-swap for that race. Use stronger native protection when available, while retaining the same portable replay rules. External tools such as plain Git do not take Waffle's read lock and can observe intermediate path installation **after Saved**. For Git staging or an external snapshot, wait for apply to finish and `.waffle/journal/active` to clear. Waffle's own readers enforce this boundary automatically.

## Git, comparison and editing sessions

**Save boundary.** Save, Save All, Save As, autosave and recovery perform zero Git operations. They work with no Git installed and with a healthy, dirty or damaged Git repository. They do not run discovery, status, hooks, index operations, staging, commits or configuration reads or writes. Ordinary saves may write the project-local `.waffle/.gitignore` as described below. Git commands are separate actions. A commit requires an explicit Commit from the user, a preview of the exact selection and a confirming Commit. The MCP and CLI `git_commit` flow likewise previews and requires the matching confirmation token. Respect the user's selected paths and leave unrelated staged changes alone. Wait for durable file installation before committing.

**Plain Git.** Two branches editing different documents touch different files. Two branches editing different non-adjacent object lines in the same document merge with an ordinary Git three-way text merge. The resulting manifest is unchanged and Git sees exactly the chosen object edits. No hook, custom merge driver, filter, Git setting or repair pass is needed. Adjacent lines, the same object, concurrent insertions at one sorted position, competing destination names or edit/delete races can produce real conflicts.

**Commit staged project files.** Stage files with your usual Git client. In Waffle, open **Project › Git › Commit…**, select the staged paths and enter a message. An explicit Commit records the selected index blobs. Saving and recovery operate on the native project files. MCP and CLI provide the same operation through `git_commit_plan` and `git_commit`. The latter requires `--allow-write`, `mode: "write"`, the returned plan token, a message and the selected paths. A change to HEAD or the staged project paths requires a fresh preview.

**Resolve Merge Conflicts** reads base, ours and theirs from the index without checking out a revision. Preserve already resolved content. Match the owner by kind and ID, then match its rows by ID. For each row, take the identical result or whichever side changed when the other equals the base. For a changed row on both sides, merge independent known fields where invariants allow. Treat coupled geometry, a document reference's kind/name/path and header capability policy as groups. For a PCB part, a side change and a separate rotation can merge when each changes a different field. The position is one `at` field, so different edits to its X and Y coordinates require one choice for the whole point. Preserve authored order keys and surviving opaque bytes. An opaque row can pass through whole when only one side changed it. Differing edits on both sides to an opaque row require a decision. Conflicting values, edit/delete, same-ID independent additions, path collisions and broken links also require a decision. Validate affected records, paths, IDs, references and geometry, and save only files whose authored content changed. The user stages the result normally. Repeating a resolution produces identical bytes. An ordinary external edit or clean Git merge needs no derived tracked change. Loading, Compare and History leave the checkout alone.

**Optional Git merge driver.** The setup command previews the repository-local config and `.gitattributes` changes for the seven native owner types. Apply only after explicit consent and a fresh check of that preview. Existing Git configuration and attribute lines outside the approved change stay intact. Git passes the driver its base, ours and theirs. On success the driver writes a validated result to Git's designated result file. On conflict it leaves that file and all three index stages intact so the user can resolve them. The driver has no project-wide view to validate cross-file links. The project reader verifies those links when it opens the result. Ordinary Save, open and recovery never install, run or update the driver.

**Compare and visual History.** Resolve each side to the manifest and the exact member files of that Git tree, index stage, saved working folder or frozen release. Changes to documents appear even if two commits share the same manifest blob. Match document and item IDs across filename changes and moves. Verified equal member digests skip geometry parsing. Fetch changed objects and required dependencies. Retain the existing semantic matcher and ambiguity review for independent foreign imports. Shared comparison results are keyed by the computed project version, compared member hashes, comparator/translator versions and options. Fetch visible history rows and thumbnails on demand. Local generated history stays under `.waffle/history/`. Authored released revisions remain in the committed closure. **Realtime collaboration and Undo.** Negotiate the format and project ID, the computed base project version and the hashes of subscribed documents. Obtain the complete version on session negotiation when needed, independently of first paint. Seed from a verified shared snapshot and causal vector before applying queued/offline edits. ### Selecting and retaining source bytes

For each imported source, hash the exact bytes passed to the isolated translator. Ordinary import Save retains authorized originals by content hash under `.waffle/imports/`. Reuse existing verified bindings. Save never queries Git to decide how to retain an original. The optional original-source flow can use a Git-backed binding only within an explicitly authorized source scope. In that flow, check the source and destination worktrees through read-only Git queries. A symlink alias, submodule or second worktree gives no evidence that two paths share a worktree. An authorized source can sit outside the project folder within that worktree. Check its regular entry, safe repository-relative path and exact byte identity before binding.

- **Git-backed original.** Record the repository-relative path, full immutable Git commit object ID with its algorithm, and raw SHA-256 of the exact imported bytes. Verify that the path names a regular blob at that commit and its decoded bytes match the source digest. The Git object ID includes Git framing and is distinct from the raw SHA-256. If the working file or index is dirty, a verified commit with identical bytes can still supply the binding. If none matches, report the mismatch and keep or obtain the verified portable bytes through the explicit original-source action. A source binding never changes the repository.
- **Portable original.** Copy the exact input bytes once under the SHA-keyed sidecar source path, regardless of repository membership. Verify the digest on installation and retrieval. Keep each per-file binding in a multi-file source set even when several bindings share content.
- **Readback.** On re-import or original comparison, try the recorded working path and use it only if its raw SHA-256 matches. On mismatch, removal or rename, read the pinned commit:path and verify again. A verified portable source copy can supply the same bytes after extraction away from that repository. A shallow clone, missing Git object or wrong repository can render original-source operations unavailable. Report the exact missing binding and offer a matching source or history object. Never silently substitute the current contents. Native editing of available documents remains independent of this optional task.

Save As can copy a retained Git-backed binding only when its portable source bytes are already present and verified. If the bytes exist only in Git history, use **File › Save as Zip** and open the extracted project to materialize them before making a new folder copy. Save As reports the missing original before creating its destination.

**File › Save as Zip** takes the same read barrier as the editor. Wait for committed apply to finish. If there are pending local edits, offer Save All and Zip, Zip Last Saved, or cancel. Write an ordinary `.zip` with one project folder. Include the manifest, all referenced live and frozen design members, libraries, compressed model files, known assets, retained import metadata and `.waffle/.gitignore`. Materialize **each retained original**, including a Git-backed one, at its logical sidecar source path in the archive after verifying its source digest. Physical storage in the archive is independent of the original working-tree storage choice. Keep the binding and manifest bytes identical and verify the same computed version before and after extraction. Stream model verification through decompression. Exclude the five ignored stores, Git internals, unreferenced project files and generated outputs. A required missing source or design member prevents claiming a self-contained archive. Report its path and publish only a finished ZIP.

Opening a project ZIP offers extraction to a fresh folder. If several projects are present, identify their roots and let the user choose. Enforce path normalization, expanded sizes and entry-count limits before and during extraction. Refuse traversal, absolute or linked entries, reparse points, device files, duplicate/colliding names and Git administration paths. Validate the extracted closure, raw source digests and model identities before atomically installing the complete folder without replacement. Outside the source repo, keep the verified portable originals so re-import and comparison work offline. Inside a matching worktree, an independently verified pinned source can supply the logical member without storing a redundant local copy. Ordinary ZIP tools can extract the archive without Waffle.

**Project › Discard Import Data** asks for confirmation explaining which source comparison, precise residuals, exact re-import and source-assisted export would be lost. Remove only the selected bindings and now-unreferenced copied source payloads through a normal transaction. Never delete a tracked source or alter Git history. Native working geometry and models remain usable. A previous Git commit may retain an old binding or copied input.

### Schematic connections, frames and page layout

The first public `2.0` schema includes the following optional design data.

| Owner | Native representation and implicit value |
|---|---|
| Off-sheet connector in `.wsch` | An `offsheet` record accepts `io` with the same four values as a port. Omit `unspecified` in canonical native bytes. The other values are `input`, `output` and `bidirectional`. The existing connector ID and electrical anchor identify the connection. |
| `schematic` header | The optional `sheet.infinite` flag selects drawing-bounds paper when true. Omit false. Retain an authored fixed paper size and orientation when the sheet becomes infinite. The existing `sheet.titleBlock` accepts `none`, `standard` or `ansi`. Its implicit value on an infinite sheet is `none`. A visible block anchors to the drawing's bottom right. Fixed sheets retain their standard default. |
| Frame in `.wsch` | Each named rectangle has one `frame` record with its own stable `id`, `at: [x,y]` for its upper-left corner, positive `w` and `h` in integer nanometres, and a nonblank `name` of up to 300 UTF-16 code units. Fixed and infinite sheets accept the same record. Frame membership is computed from geometry. The frame introduces no net or electrical anchor. |
| Generated net label in `.wsch` | A `netlabel` may carry `autoName: {part, pin, style}`. The first two fields are a nonblank stable placed-part ID and the nonblank pin-number string. A label retains its ordinary literal `text`. Omit the entire optional object when the label has no pin-based naming rule. |
| PDF entry of an authored output job in the manifest | `options.infiniteLayout` accepts `fit`, `frames` or `tile`. Omit the default `fit`. `options.infiniteScale` is the positive, dimensionless ratio of printed length to drawing length for tiling. Use the canonical decimal string representation, including for integral ratios, and omit 1. For example, `"0.75"` prints at 75%. |

A fragment from an infinite sheet with its fixed A3 paper retained shows the canonical key order.

```jsonl
{"kind":"schematic","formatVersion":"2.0","id":"s1","sheet":{"infinite":true,"size":"A3"}}
{"kind":"frame","id":"f1","at":[-75000000,-40000000],"h":65000000,"name":"Analogue inputs","w":90000000}
{"kind":"offsheet","id":"n1","at":[-60000000,-25000000],"io":"output","text":"SENSE"}
```

A native frame retains its stable ID, name, authored rectangle and appearance. The live editor represents it as a text frame with the frame role. The projection uses the canonical millimetre-to-nanometre conversion for its rectangle. Ordinary text annotations retain their own kind. Off-sheet direction and sheet flags map directly.

Converting a frame to a child sheet keeps its ID on the replacement sheet symbol. Moved objects keep their IDs. If a wire or bus must split, the fragment with its original first vertex keeps the ID. Allocate fresh IDs for the other fragments, child document, ports and sheet entries. The existing cross-document Undo and save rules apply.

Frame extraction may need to preserve the original automatic name of an otherwise unnamed net inside repeated channels. Author `autoName` only on the generated net label when the conversion needs that identity. At compilation, an explicit user net name takes priority. Resolve the recorded part and pin within the current compiled net and instance, or use its unique matching endpoint after an object moves to an adjacent sheet. The `hyphen` style gives `Net-<physical designator>-<pin>`, and `underscore` gives `Net<physical designator>_<pin>`. A missing, disconnected or ambiguous target uses the literal text under ordinary channel naming rules. A newer minor's unknown style also uses the literal text and preserves the complete object. Net connectivity and pin unions are computed from the existing sheet wiring. Frame conversion verifies physical names and pin partitions before the transaction.

The native record retains its stable ID, literal text and complete pin-based `autoName` rule through an editor round-trip. Altium and KiCad receive literal net labels, and their fidelity reports identify the loss of dynamic channel naming. ### Engineering notebook

Apricot Preview writes the notebook as native **2.0**. Each authored placement has its own stable ID and sheet row. Rich text, equations, calculations, widgets and Notes use `at`, `w` and `h` in integer nanometres. An image uses `x`, `y`, `w` and `h` in those units. Paint order follows the existing owner order keys.

| Owner and kind | Authored fields |
|---|---|
| Sheet `richtext` | Readable `text` and `richText` with an optional `font`, ordered `blocks`, and each block's ordered `runs`. Text runs own marks and links. A sticky note adds `sticky.colour`. A callout adds `callout.colour` and `callout.anchor` with the target document, optional object, pin and instance IDs, and its last authored fallback `at`. |

Binding `span` is a half-open range of UTF-16 code units. |
