# One query language for Waffle

**Approved with amendments for Apricot.** Apricot ships the shared compiler and uses it for native 2.0 rule scopes. The existing Filter presents its familiar spelling and translates it in memory. Butter adds the cross-editor interfaces and saved smart groups described below. The first published native rule representation is the same one later tools consume.

## What a query selects

| Query | Result |
| --- | --- |
| `resistor where value < 1k and sheet = Power` | Resistor values below 1 kΩ on the Power sheet. The resistor value field declares Ω. |
| `part where value < 1 kΩ` | Among mixed parts, test values whose declared dimension is resistance. `part where value < 1k` requests a unit because the generic field can represent more than one dimension. |
| `net in class HighSpeed and length > 50 mm` | Members of the board’s HighSpeed net class whose routed length exceeds 50 mm using the same measurement as Length Tuning. |
| `pad on layer Top near U3 within 2 mm` | Pads whose copper edge is at most 2 mm from U3’s transformed body/courtyard. Through pads include every layer they span. |
| `pad near origin of U3 within 2 mm` | Measure the candidate pad edge to U3’s actual placement origin. A rotated, offset or bottom-side footprint can give different results from the body query. |
| `track where width < rule(MinWidth)` | Tracks below the effective minimum of their winning width rule, including layer and stack region. |
| `assert count(track where width < 0.15 mm) = 0 ea` | A complete selection supplies a count in pieces. The calculation owns the assertion and its finding. |

`near` is inclusive. Use the existing clearance geometry for transformed copper/drills, physical outlines and part bodies/courtyards, with an index rectangle only to obtain candidates. Body selection and any supported geometric fallback must be identical to the corresponding clearance provider and disclosed in the result. An unavailable body, unresolved anchor or incompatible coordinate space carries a diagnostic. A footprint bounding-box centre cannot stand in for its authored placement origin. Repeated panel or sheet instances use their own transforms.

## Grammar and values

The outer parser composes row types and Boolean conditions. The calculation lexer and scalar evaluator own original-case Unicode, decimals, suffixes, powers, arithmetic, conversion, functions and half-open UTF-16 spans. Boolean words are case-insensitive. The spelling `||` inside a native scalar means electrical parallel. The word `or` combines conditions. `in class` is a relation, while an inch literal or conversion stays in the scalar grammar.

```ebnf
query       = kind [ "where" predicate | relation { relation } { "and" unary } { "or" conjunction } ]
predicate   = conjunction { "or" conjunction }
conjunction = unary { "and" unary }
unary       = "not" unary | "(" predicate ")" | relation { relation } | test
relation    = "in" family name | "on" "layer" name
            | "near" [ "origin" "of" ] name "within" scalar
test        = field compare operand | scalar compare scalar | boolean_field
compare     = "=" | "!=" | "<" | "<=" | ">" | ">=" | "like" [ "case" ]
```

Adjacent relations imply `and`, as in the top-pad example. Adjacent comparisons require a Boolean word. Supported relation families include class, net, component, component class, pair, pair class, signal, tag, xSignal, room and polygon where the row type supports them. Bind an identity such as `sheet = Power` or `near U3` by type in its document and occurrence. Names with spaces or punctuation accept either quote delimiter and backslash escaping. A literal such as `designator = "U3"` compares the displayed field. `object` means the consuming rule’s eligible objects. A concrete kind narrows that domain.

- Text `=` compares exact Unicode scalar values and case. If an exact search finishes empty and a visible case-folded equivalent exists, suggest the alternative. The result and saved source change only on user selection. `like` matches a whole case-folded string with the bounded glob operators `*` and `?`. `like case` uses the same glob with exact case. Neither depends on the host locale. Typed quantity comparisons use the calculation language’s binary64 relative equality and its closed-boundary semantics before display rounding.
- A field declaration supplies type, quantity dimension and display/input unit. Built-ins include resistor value in Ω, capacitor value in F, track width and routed length in mm, power in W, voltage in V, tolerance in % and temperature coefficient in ppm/K. A custom project or library field can declare its unit. Placement overrides retain the declaration unless the normal field resolver supplies a more specific one. Conflicting declarations, a broken field ID and an unknown unit identify the owning declaration.
- A bare numeric marking such as `1k` directly opposite one declared field in a comparison takes that field’s unit. This includes an ordinary number, e.g. `track where width < 0.2` on the declared mm field. Engineering prefixes preserve case. A typed resistance reads `1k` as 1 kΩ, typed power reads `1m` as 1 mW and a declared tolerance reads `5` as 5%. Explicit compatible units always work. An explicit incompatible unit on a single declared field produces a located error. On a polymorphic value an explicit unit selects compatible rows. A generic or undeclared field requests an explicit unit. The quick fix can open its project/library declaration. Use the shared declaration resolver for the resulting edit. Outside a single-field comparison the calculation language’s scalar rules apply. For instance, `10k * 10n` is still dimensionless. The selected part and the previous query confer no units.
- `count` has a count quantity dimension and uses `ea` (alias `pcs`). It can compare with a count. An explicitly dimensionless ratio or physical unit is incompatible. The calculation and query services share quantity types, counts and declared-field unit hints. Nominal row filtering and interval-based calculation assertions use their respective existing projections. A row missing an optional field has unknown truth, including under negation. False dominates `and` and true dominates `or`. Only true rows match. An unavailable required measurement, unresolved binding, cancelled job or exhausted budget leaves affected checks incomplete.

## Native record and exchange

The native rule and its optional second side each store the following value in the **first published 2.0** format. Each rule retains its stable rule ID, owner, priority, enabled state, constraints and check-specific application policy.

```json
{"languageVersion":1,"source":"track where width < 0.2 mm"}
```

`source` preserves original text. Optional `bindings` identify occurrences by stable occurrence ID, half-open span, target document/object or signal ID, field key and hierarchy instance where applicable, using the calculation binding convention. New saved references follow an ID through renames and moves. A different object reusing its label leaves the original binding broken. Undo restoring the same ID repairs it. An ephemeral name resolves anew. Name-valued comparisons intentionally follow their current text. Native 2.0 readers/writers, workers and headless tools understand `languageVersion:1` without an extra required-feature header. An unknown language version remains explicit and incomplete. Never report a certified clean result for a rule whose applicability is unknown. [Format 2 records and IDs](format-2.md) · [Calculation bindings](calculations.md)

Project groups arrive in Butter as an additive 2.x manifest record with immutable ID, name, source, version, stable bindings, scope and optional column field keys. Use the common format registry’s next additive minor only when persisting that record. An older reader can retain an unused group opaquely alongside unrelated edits. Current results, counts, plans and recents stay outside authored records. An existing 2.0 rule does not need a later smart-group record to work.

### Existing scopes

Compile eligible subjects under their original rule family and preserve the meaning of both sides. The native syntax has one set of comparison and membership semantics. Temporary in-memory adapters project preview-era structured selectors and the current Filter controls to it. A consumer does not persist an old grammar, comparator, collation or an embedded expression interpreter.

| Previous scope | Native meaning |
| --- | --- |
| All | `object`, within the current check’s domain. |
| Net or component | Literal `net.name = "GND"` or `component.designator = "U3"` preserves a name-valued selector. A stable reference is a separate authored choice. |
| Net class or component class | Typed membership in the declared class with the owner’s All Nets/All Components behavior. ERC uses its existing cross-board class projection. |
| Differential pair and pair class | Membership includes the relevant legs/stages and pair-class memberships from the signal model. |
| Layer | Physical layer membership includes the actual inclusive span of via/pad copper. |
| Signal and tag | Membership includes the signal’s stages, bus members and applicable tag projections. |
| Existing custom filter | Lower recognized predicates, fields, functions and Boolean operators into native v1 conditions before compiling. Keep a locator for a foreign source and a located diagnostic for anything unmapped. |

Apricot’s existing Filter is a transient input surface. Its adapter may parse the familiar syntax in memory and pass only native expressions to the compiler. Direct authoring, saved native rule scopes and the shared plan use v1. A text case mismatch or a numeric boundary is evaluated under the approved native semantics. Tests name those intended behavior changes. An unsupported operand cannot become an all-objects or empty-success substitute.

Altium rule interchange uses its published grammar and stored format, including `.RUL`, ASCII PCB records, binary Rules6, legacy indexed selectors and both scope expressions. Translate supported functions, compounds, units, physical layers, paired roles and rule constraints into v1. Preserve enabled state, priority, source locator and verified provenance. On export generate target Altium syntax from the checked native form, quoting names correctly. Report per source rule and side as kept, approximated or dropped with the reason. A dynamic tag expanded into a particular set of nets is an approximation. An unsupported operand in an active OR or on one side of a pair prevents enforcement of the affected rule. Retaining original bytes and enforcing the rule are separate report facts. The pinned R6 PiDP-11 translator accounts for 41 real source rules, 27 kept or approximated. ## Compiler and evaluation contract

The small pure `AtriumDesignQueryRecord` provides `create(source,bindings?)`, `valid(record,{allowUnknown?})`, `copy(record)`, `fromSelector({kind,value?})`, its convenience form `selector(kind,value?)`, `toSelector(record)` for exactly recognizable simple forms, and `isAll(record)`. Use the plain source `object` for all. For net/component emit the exact literal field tests in the table above. For net class, component class, differential pair, pair class, signal, tag and layer, use respectively `object in class`, `object in component class`, `object in pair`, `object in pair class`, `object in signal`, `object in tag` and `object on layer` followed by a quoted name. Preserve a complex or bound source intact when the simple picker cannot represent it. A binding has `{id,name,span:[start,end],target?}`. A target uses the calculation binding fields such as `scope`, `docId`, `itemId`, `signalId`, `field` and `instanceId`. Normal authoring validates known fields. A future-minor reader can retain additional annotations on the owned record. An unsupported language or required predicate is a check diagnostic.

The lazy `AtriumDesignQuery.compile(scope,context)` returns `{ok,diagnostics,hints,plan?}`. Diagnostics and completion edits refer to the original UTF-16 source. Context supplies `domain`, optional project/document, `resolveRef({family,name,span,binding})` returning `{target}` or `{diagnostic}`, and optional `relation(subject,family,target)`, `fieldValue(subject,key,declaration)` and `ruleValue(subject,key)` providers. A target includes its source name and resolved stable identity. `plan.test(subject)` returns true, false or unknown (null); `matches(subject)` selects true rows. Plans expose normalized typed operations, `dependencies` and safe `indexTerms`. `plan.run(index,{signal,limit,onPage})` streams qualified subjects at one revision. Positive conjuncts can restrict indexed candidates. Under negation or a disjunction, any restriction must cover every possible match.

After binding a geometry anchor, call `context.geometry.prepareNear({anchor,mode,radius,kind})`. Radius is a nonnegative length in mm, frozen independently of the candidate. The provider returns `{ok,diagnostic?,bounds?,matches(subject),dependencies}`. `index.spatial(bounds)` supplies broadphase candidates. The exact three-valued residual uses transformed subject edges against the target body or its explicitly chosen origin. Use the clearance provider’s documented surface and fallback, preserving holes and cutouts. Touching has zero gap on the closed boundary. `AtriumDesignQuery.count(source,{project,documentId,instanceId,revision,signal})` returns an asynchronous `{count,complete:true}` at the captured revision, or a diagnostic with its source span. It uses the same plans/indexes and publishes an exact count only when evaluation is complete.

| Boundary | Owner and behavior |
| --- | --- |
| Language | Query core owns token interpretation, Boolean parsing, kind/field type checks, record validation, source spans, binding/plan compilation and bounded execution. It reuses the shared calculation lexer and quantity services. |
| Field declarations, count and hints | The units owner provides stable declaration keys, dimension and unit metadata, typed bound values, count units and inferred-unit hints used by 36/42/43. Existing autocomplete presents the field’s unit and a ghost unit for a contextual marking. An undeclared custom field offers its existing declaration editor. |
| Rule subjects and exchange | The DRC/ERC owner supplies subject projections, typed class/identity membership, effective rules and application policy. The translator owner maps each Altium record/side both ways. These adapters use the compiled plan. The existing Filter passes native values in memory. |
| Geometry | The spatial owner supplies indexed candidates plus exact distance for the body/courtyard or explicit placement-origin mode in common world coordinates. The compiler binds anchor, mode and radius once. |
| Selection and tools | Consumers take read results; a deliberate UI selection uses the ordinary host selection call and a user jump uses the navigation/camera API. Headless reads return references and typed fields. Extension requests require `read:project` and the existing approval boundary for edits. |

For DRC preserve first-match, either-endpoint, symmetric pair, directed reference and accumulating policies. A symmetrical pair satisfies `A(a) and B(b)` or the swapped roles and deduplicates the qualified pair. Forward/return nets retain their direction. Filter only the candidates supplied by the check’s broadphase or connectivity relation. WASM clearance, pour bands, DRC certificates and ERC kernels still measure and decide findings. Rule preview uses the same eligible domain, memberships, winning priorities and snapshot. The linter distinguishes proven impossible predicates, complete priority shadows, contradictory limits and exact project-local emptiness. Opaque predicates or proof limits yield unknown. A cycle involving `rule(MinWidth)`, a scoped rule or an assertion names the dependency cycle. ### Performance, cancellation and authority

1. Intersect kind, layer, net-class, spatial, designator and typed parameter postings before bounded compiled residual checks. Reuse existing connectivity, measurement and rule indexes. Count intersections directly where possible. A broad first use can construct missing postings in worker batches. A cold, empty Home and a design with no relevant request perform zero query/authoring-module loads on this feature’s behalf.
2. Cache syntax by source and language version, and plans by normalized typed operations, binding IDs, field/function versions, domain, active configuration and authority. Results and cursors are tied to snapshot, project, scope, instance, projection and permission. Sort stable qualified IDs for reproducible paging. Reuse unaffected memberships after consuming committed deltas.
3. Each subscriber reads `AtriumUndoStore.recordedChanges(doc,lastAcceptedSeq)` through the edit pipeline. Retain old lookup keys, memberships and bounds. A width edit rechecks the touched track; moving U3 invalidates its old and new windows. A reclassified net updates its affected classes and measurements, and a library declaration invalidates its field users. Undo, redo, remote changes, deletion and rebinding follow the same path. Wait for unsettled connectivity. On a journal gap rebuild the affected partition. Advance the cursor only after acceptance. [Edit pipeline](../app/editor/edit-pipeline.js) · [Undo journal](../app/history/undo-store.js) · [Spatial index](../app/core/spatial.js)
4. Publish first indexed matches within **16 ms** of a warm request. Stream an exact count later when necessary. Complex queries target **p95 ≤50 ms** to initial results. Show “Counting…” or a lower bound while work is pending. An exact zero is displayed only after completion. Cancel obsolete text, snapshot, scope or grants; check cancellation at bounded work intervals and before publication. Discard stale pages. A headless read, assertion or macro receives explicit completion, incomplete, cancelled, stale or denied status.
5. Apply allowed project/documents, fields and grants before planning, autocomplete, counts, diagnostics and cache reuse. Paginate bounded copied references and projections. Enforce input, nesting, expansion, CPU and memory budgets cumulatively across nested queries/pages. A denied caller learns no hidden label or count. Queries never execute scripts or change designs. An accepted macro/edit proposal rechecks its reviewed revision.

## Butter consumers and acceptance

Palette search and `@` keep fuzzy words or a single designator and route structured input to this core. Select/Filter applies IDs through the existing public selection and overlay paths. “Show what this rule applies to” distinguishes scope sides, eligible pairs, priority winners and violations. BOM filters source occurrences before grouping. Navigator smart groups, widgets, tables, calculations, macros, MCP, AI tools and extensions share the same qualified references and snapshot. A printed widget uses its frozen export revision. A reusable macro exposes a named bound occurrence as a typed parameter. A new engine or UI per consumer would break cross-surface result parity.
