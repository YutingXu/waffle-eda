# AtriumAPI v1 reference

_Generated by `scripts/gen-extension-api.py` from `app/core/atrium-api.js` and `app/extension-host/extensions.js`. Do not edit: change the source or `scripts/extension_api_notes.py`, then run `python3 scripts/gen-extension-api.py` (CI runs it with `--check`)._

Extensions, console scripts and MCP `run_script` all program against this one object, `api`. In an extension every call is a message from its sandboxed worker to the editor, which checks the extension's permissions on every call, so **every call returns a Promise**: write `await`. Reads return copies. Lengths are millimetres, points are `[x, y]`. Calls marked *runs in the worker* need no permission and send no message.

New to extensions? Start with [extensions.md](extensions.md) (a first extension in 15 minutes), the examples in `extensions/examples/`, and `scripts/new-extension.py`. Console scripts: [scripting.md](scripting.md).

## Permissions

Declare capabilities under `permissions` in `waffle-extension.json`. Browse Extensions and direct package installation use this same list. Revoking a permission takes effect on the next call. [API version compatibility](upgrading.md#extensions)

| Permission | What it allows (as the install prompt says it) |
| --- | --- |
| `read:motion` | Read the editor’s animation policy, timings and active track count |
| `read:project` | Read the design: documents, objects, nets, rules and selection |
| `ai:provider` | Respond to AI requests with only the approved project fields |
| `propose:edits` | Propose changes to the design; nothing changes until you review and apply them |
| `write:edits` | Apply approved edits to this project |
| `outputs:write` | Save files through the system save dialog |
| `ui:panel` | Show panels in the right dock or a floating window |
| `ui:widgets` | Render notebook widgets and update their own state on interaction |
| `ui:command` | Add commands, menu items, toolbar buttons, shortcuts and status items |
| `ui:decorations` | Draw read-only labels, probes and markers on the canvas (removed when it stops) |
| `run:external` | Run programs you installed and choose in Preferences › External Tools (you approve each one) |
| `network:<host>` | Contact `https://<host>` through the host-mediated `fetch` (off until the user allows it) |
| `network:localhost` | Contact servers on this computer (localhost, any port; off until the user allows it) |

Console scripts can read and edit the design, export files and show dialogs. MCP `run_script` reads a project copy. Persisting an edit requires an explicitly writable server and write mode. [Headless scripting](scripting.md#headless-mcp-and-the-command-line)

## Palette contributions

`contributes.insertItems` and `contributes.paletteCommands` add entries to Waffle’s existing search palette. Each entry has an extension-local `id`, a `name` and the `command` registered by the package’s `activate(api)` function. Optional fields include `description`, `keywords` (string array), a local sprite `icon`, a short text or PNG `preview`, `contexts` (editor kinds such as `schematic` and `pcb`) and `actions` (`{id,label}` pairs). Declare the existing `ui:command` permission. Waffle can index these declarations before starting the extension. The same entries are available to the palette’s alias and shortcut preferences.

```json
{"permissions":["ui:command"],"contributes":{"paletteCommands":[
  {"id":"browse","name":"Browse packages","command":"packages.browse","keywords":["footprints"],"icon":"chip"}
]}}
```

Register the handler with `api.commands.register("packages.browse", event => …)`. Opening a row sends `{type:"open",query,editorKind}`. Choosing an action sends `{type:"action",actionId,itemId?,query,editorKind}`. Submitting a form sends `{type:"submit",actionId,values,query,editorKind}`. A user-invoked command with a live `read:project` grant also receives the captured `documentId` and finite `[x,y]` placement `point` when available. Use existing `api` reads for anything else. IDs returned by screen items and actions go back only to this same command in this same installed package. A command can return another screen, enabling native Back navigation. Use `api.transaction` or `api.proposals` for design changes. An approved proposal commits through the editor’s existing Undo history.

### Declarative screens

| `kind` | Fields |
| --- | --- |
| `list`, `grid` | `title`, `text`, `items`. Each item has `id`, `label` and optional `detail`, `accessory`, `icon`, `disabled`, `thumbnail` and item-scoped `actions`. |
| `detail` | `title`, `text`, `blocks`, `primary`, `actions`. Blocks can be `{kind:"text",text}`, `{kind:"math",text}`, `{kind:"richText",body}` or `{kind:"image",image}`. Use TeX in a math block or notebook math run. The bundled typesetter supplies scalable glyphs and an accessible transcription. Unsupported expressions remain readable as entered. |
| `form` | `title`, `text`, `fields`, `primary:{id,label}`. Each field has `id`, `label`, `type` (`text`, `number` or `select`), optional `value` and `required`. Numeric fields support `min` and `max`, text fields `maxLength`, and select fields `choices:[{id,label}]`. The host validates submitted fields and sends finite numbers for numeric fields. |
| `calculation` | `title`, `functionId`, exact `version`, `arguments:[{value,dimension}]`. The host asks the shared calculation worker to evaluate a function owned by the extension. Optional `blocks` use the Detail format and appear with its formatted result. A dimension or domain error appears in the current palette. |

Waffle renders text, icons and controls itself. A packaged PNG uses `{kind:"png",data:"data:image/png;base64,…",alt:"…"}`. Images are limited to 512 × 512 pixels and 88,000 URI characters. Screen models are limited to 512 KiB, 80 items, 32 detail blocks, 16 form fields and 12 actions per list. The live editor, DOM nodes, navigation functions and executable handlers are outside the screen protocol.

A `richText` body uses the notebook’s static paragraph grammar. Each `body.blocks` entry has a `style` (`paragraph`, `h1`, `h2`, `h3`, `bullet`, `number` or `check`) and `runs`. A checklist entry accepts a boolean `checked`. Runs are `{type:"text",text}` or `{type:"math",tex}`, with optional boolean `bold`, `italic`, `underline`, `strike` and `code` marks. Use ordinary text for literal markup. The view reads no project fields and activates no links. Each rich body accepts 16 paragraphs, 32 runs per paragraph and 8,192 characters. A Detail displays up to 256 rich runs and 16,384 rich characters. Its first 32 formulas can use up to two million raster pixels in total. Further formulas retain readable source.

### Streaming search

Declare up to four `contributes.searchProviders` per extension. Each entry uses `id`, `name`, `command`, a packaged JavaScript `module`, optional local JSON `data`, and a `hosts` array. Every host must match an exact `network:<host>` permission on the same manifest. The existing install or trust dialog asks about the hosts once per extension. Users can change the individual grants in Tools › Extensions.

```js
// search.js, with a packaged stock catalogue named by the provider’s data field
exports.search = async ({query, editorKind}, {signal, emit, data}) => {
  for (const part of data) {
    if (signal.aborted) return;
    if (part.label.toLowerCase().includes(query.toLowerCase())) {
      emit([{id: part.id, label: part.label, accessory: String(part.stock)}]);
    }
  }
};
```

Providers run in fresh, read-only workers. The search module receives the query and editor kind. `emit(rows)` sends partial results. Returning an array sends a final batch. Rows use the list item fields and stable extension-local IDs. Choosing a result invokes the provider’s declared command with its `itemId`. The host supplies its source name, icon and stable row key and appends streamed rows below existing local results. Stale batches are discarded on a new query or close. Pass `signal` to `fetch` when using a live service. Only declared, currently approved hosts accept GET or HEAD, with redirects disabled and credentials omitted. Providers cannot read the project, invoke commands, persist data or edit a design while searching.

A provider can start four times per second with a two-second response deadline. During a burst only the latest waiting query is kept. Each search can return at most eight chunks and 24 distinct rows. The palette also applies its aggregate limits across providers. A provider’s missing grant, timeout or unavailable service leaves the other sources responsive.

### Pure calculation functions

`contributes.mathFunctions` declares versioned functions in the shared calculation language. An ID consists of the complete package ID followed by a single function name. `arguments` is an array of named dimensions (up to 16), `returns` names the result dimension, `domain` is a predicate or a list of predicates, and `expression` is the pure calculation body. Optional `dependencies` are `{id,version}` pins. The computation worker receives these declarations and quantities in base SI units. When the shared evaluator is available, installing or enabling a package checks its expression and domain with the same parser used by sheets. An invalid update preserves the installed version. The installed package digest and exact function version identify the implementation. The host checks dimensions, finite results and cancellation and reports unavailable versions. The same function declaration can be used on a sheet and in a palette Form. The package’s normal JavaScript, grants and project data are outside this arithmetic interface.

```json
{"id":"example.divider.vout","version":"1.0.0",
 "arguments":[{"name":"vin","dimension":"voltage"},{"name":"rtop","dimension":"resistance"},{"name":"rbottom","dimension":"resistance"}],
 "returns":"voltage","domain":["rtop >= 0 ohm","rbottom > 0 ohm"],
 "expression":"vin * rbottom / (rtop + rbottom)"}
```

Complete examples are [Benchstock’s stub distributor](../extensions/examples/palette-distributor/), [live project footprint grid](../extensions/examples/palette-footprints/) and [voltage divider Form](../extensions/examples/palette-calculator/). The distributor sample uses a packaged stock fixture. The footprint browser builds pad thumbnails and proposes placement on the active board. The calculator delegates a 5 V, 1 kΩ and 2 kΩ divider to the same pure function used by sheets, yielding 3.333 V. A build without the shared evaluator displays its availability inline.

## Sheet widgets

A package declares notebook block types under `contributes.widgets`. Each type has a local
`id`, a visible `name`, a `render` command and an optional `event` command. Declare both
commands in this package and grant `ui:command` and `ui:widgets`. A design input also requires
the current `read:project` grant. Disabled packages and missing grants display the saved fallback.

| Declaration | Accepted values |
| --- | --- |
| `state` | Named properties of type `string` with `maxLength` and `default`, `number` with `min`, `max` and `default`, or `boolean` with `default`. A `list` declares `maxItems` and primitive `fields`. Its rows have stable string IDs. |
| `inputs` | Up to 16 uniquely keyed fields or calculation references. Use `{key,kind:"field",expression}` or `{key,kind:"calculation",documentId,blockId,instanceId?}`. |
| `size` | Minimum, preferred and maximum `[width,height]` in millimetres, between 4 and 400 per dimension. The command receives the negotiated size. |
| `fallback` | `{type:"text",text}` or `{type:"image",assetRef,alt}` with a project `{sha256,mediaType,byteLength}` asset reference. Text or alt remains readable when the asset or package is unavailable. |

The worker receives `{state,inputs,size,theme,tokens,event}`. It returns `{title,rows}`, where
each row contains an array of `{text,token?}` cells and optional `checked` and `action` values.
Use the supplied tokens for ink, muted text, accents, links, warnings and broken references.
An interactive row receives keyboard activation, focus and touch through the optional event
command. Return `{state}` with the declared fields to update in a single undo. A returned
list sets that list's row membership and order.
Only user input can change state. A render callback has no DOM or canvas handle.

The worker sees declared fields only. A missing primitive field uses its declared default,
and a missing list appears empty. The host keeps unfamiliar saved fields, including list fields
attached to surviving row IDs. A present value must satisfy its declared type and bounds.

Each extension gets one in-flight widget callback and at most four paint requests per second.
The host stops its worker on a 160 ms callback timeout. The renderer accepts up to 48 rows,
eight cells per row and 32 KiB per response. Other sheet objects continue painting during
a worker request. The persisted fallback also serves export when a live view is unavailable.

Two complete installable samples live under `extensions/examples`:

- [Inspection counter](../extensions/examples/widget-inspection/waffle-extension.json) stores a bounded count and increments it from an actionable row. Its [worker](../extensions/examples/widget-inspection/main.js) handles touch and keyboard.
- [Rail specification](../extensions/examples/widget-rail/waffle-extension.json) displays a live design field with the current net voltage. Its [worker](../extensions/examples/widget-rail/main.js) marks an unavailable field with the broken-reference token.

## Limits

| Limit | Value |
| --- | --- |
| Command time | 5 s by default; manifest `timeoutMs` up to 120 s, or 10 min with `"worker": "dedicated"`. At the limit the worker is terminated. |
| Background CPU | 5 s of processor time per 10 s outside a running command, and a heartbeat every 1 s (silence for 20 s stops the worker). |
| Idle | An active extension with nothing open or pending stops after 10 min and restarts on demand. |
| API calls | 2,000 per second per extension. |
| Message size | 16 MB per message. |
| Objects per read | 20,000; page with `limit` and `offset`, or narrow the filter. |
| Operations per transaction | 200,000. |
| Operations per proposal | 500,000. |
| Panel view | 1 MB of data per view. |
| Panel elements | 20,000 rendered nodes per view (long tables are cut with a note), 64 columns, 200 form fields, 200 buttons, nesting depth 16. |
| Messages rows | 2,000 per `ui.showMessage` call. |
| Storage | 256 KB per JSON value. |
| Log lines | 50 per second; the rest of that second is dropped. |
| Dialogs | One per extension at a time and 3 queued consent prompts; an extension whose dialogs are dismissed 5 times in 30 s is disabled. |
| Network | 8 open responses per extension. |
| Network response | 64 MB per response. |
| Package | 32 MB per package. |

Users can stop everything with **Ctrl/⌘+Shift+Esc**, **Esc** three times while extension work runs, or **Pause all** in Tools › Extensions.

## Project

The open project as a whole.

<a id="api-project-info"></a>
### `api.project.info()`

Name, units, revision and a summary of every document.

- **Permission:** read:project
- **Returns:** `{name, units, apiVersion, revision, activeDocument, documents: [{id, name, kind, grid, itemCount}], libraryCount, extensions}`

```js
const {name, documents} = await api.project.info();
console.log(name, documents.length + " documents");
```

<a id="api-project-netlist"></a>
### `api.project.netlist(options)`

The schematic netlist as JSON, or as SPICE text.

- **Permission:** read:project
- **Parameters:**
  - `options` (object): `{format: "json" | "spice", doc}`. Without `doc`, every sheet (nets with the same name join across sheets).
- **Returns:** `{project, components: [{id, ref, value, definition, footprint, sheet, pins: [{number, name, net, fn?, unit?}]}], nets: [{name, pins: ["R1.1", …]}]}`; with `format: "spice"` also `text`.

```js
const net = await api.project.netlist({format: "spice"});
console.log(net.text.split("\n")[0]);
```

## Documents

Schematic sheets and board layouts.

<a id="api-documents-list"></a>
### `api.documents.list()`

Every document.

- **Permission:** read:project
- **Returns:** `[{id, name, kind: "schematic" | "pcb" | …, grid, itemCount}]`

```js
const boards = (await api.documents.list()).filter(d => d.kind === "pcb");
```

<a id="api-documents-active"></a>
### `api.documents.active()`

The document the user is looking at.

- **Permission:** read:project
- **Returns:** `{id, name, kind, grid, itemCount, outline}`

```js
const doc = await api.documents.active();
if (doc.kind !== "pcb") throw Error("Open a board first.");
```

<a id="api-documents-get"></a>
### `api.documents.get(id, options)`

One document, optionally with its objects.

- **Permission:** read:project
- **Parameters:**
  - `id` (string): Document id.
  - `options` (object): `{items: true, kind, fields, limit, …}`: include objects, filtered as in `items.list`.
- **Returns:** `{id, name, kind, grid, itemCount, outline, notes, items?}`
- **Limit:** Objects per read: 20,000; page with `limit` and `offset`, or narrow the filter.

```js
const d = await api.documents.get(id, {items: true, kind: "via", fields: ["id", "x", "y"]});
```

<a id="api-documents-activate"></a>
### `api.documents.activate(id)`

Switch the editor to another document.

- **Permission:** ui:panel or ui:command
- **Parameters:**
  - `id` (string): Document id.
- **Returns:** `true`

```js
await api.documents.activate(boardId);
```

## Objects

Parts, wires, tracks, vias, pads, labels and graphics on a document.

<a id="api-items-page"></a>
### `api.items.page(filter)`

Return one bounded page and its total from the same document, ordering and filter.

- **Permission:** read:project
- **Parameters:**
  - `filter` (object): As items.list, including bounds, offset, limit and fields. The default page size is 50.
- **Returns:** `{items, total, next_offset}`

```js
const page = await api.items.page({kind: "track", offset: 50, limit: 25});
```

<a id="api-items-list"></a>
### `api.items.list(filter)`

Objects on a document, filtered. Returns copies.

- **Permission:** read:project
- **Parameters:**
  - `filter` (object): `{doc, kind, kinds, ids, layer, net, where: {field: value}, bounds: [x0, y0, x1, y1], fields, limit, offset}`. `fields` picks the properties to copy; use it, it keeps messages small.
- **Returns:** `[object]`: each a copy with the requested `fields` (all fields when omitted).
- **Limit:** Objects per read: 20,000; page with `limit` and `offset`, or narrow the filter.

```js
const tracks = await api.items.list({kind: "track", net: "GND", fields: ["id", "width", "points"]});
```

<a id="api-items-get"></a>
### `api.items.get(id, options)`

One object by id, from any document.

- **Permission:** read:project
- **Parameters:**
  - `id` (string): Object id.
  - `options` (object): `{fields}`.
- **Returns:** The object plus `document` (its document id), or `null`.

```js
const t = await api.items.get(id, {fields: ["width", "layer"]});
```

<a id="api-items-count"></a>
### `api.items.count(filter)`

How many objects match a filter (no limit applies).

- **Permission:** read:project
- **Parameters:**
  - `filter` (object): As `items.list`.
- **Returns:** `number`

```js
const vias = await api.items.count({kind: "via"});
```

## Library

Component definitions (symbol, footprint, parameters) used by the project.

<a id="api-defs-list"></a>
### `api.defs.list(options)`

The project's component definitions.

- **Permission:** read:project
- **Parameters:**
  - `options` (object): `{fields}`. Without `fields`: `{id, name, prefix, value, category, symbol: boolean, footprint: name}`.
- **Returns:** `[definition summary]`

```js
const defs = new Map((await api.defs.list()).map(d => [d.id, d]));
```

<a id="api-defs-get"></a>
### `api.defs.get(id)`

One definition in full: symbol, footprint (pads, shapes), parameters.

- **Permission:** read:project
- **Parameters:**
  - `id` (string): Definition id (a part's `def`).
- **Returns:** The definition, or `null`.

```js
const def = await api.defs.get(part.def);
console.log(def.footprint?.pads.length);
```

## Parts

Pins and pads of a placed component.

<a id="api-parts-pins"></a>
### `api.parts.pins(partId)`

Pins (schematic) or pads (board) of a placed component, in world coordinates.

## Edits

Every change is a guarded proposal applied as one undo step.

<a id="api-transaction"></a>
### `api.transaction(label, fn)`

Collect edits and apply them as one guarded proposal and one undo step.

- **Permission:** propose:edits or write:edits
- **Parameters:**
  - `label` (string): Undo label (optional; `transaction(fn)` works).
  - `fn` (function(tx)): Called once with `tx`: `add(item, {doc}) → id`, `update(id, patch)` (`null` deletes a field; `id` and `kind` never change), `move(id, dx, dy)`, `transform(id, {x, y, angle})` (parts), `remove(id | ids)`, `setDocument(doc, {name, grid, outline})`, `addDefinition(def) → id`, `select(ids)`. May be async.
- **Returns:** `{applied, added: [ids], removed, result}`; `{applied: 0, declined: true}` when the user discards a review. `result` is what `fn` returned.
- **Limit:** Operations per transaction: 200,000.

Every operation is checked against the model rules and the whole project is validated afterwards; if anything fails, nothing changes and the error names the operation. With `propose:edits` the user reviews the changes and may keep a subset. Reads inside `fn` see the project as it was before. Object kinds that can be added: part, wire, track, graphic, label, netlabel, junction, via, pad.

```js
const r = await api.transaction("Widen power", tx => {
  for (const t of tracks) tx.update(t.id, {width: 0.5});
});
console.log(r.applied + " changes");
```

<a id="api-proposals-draft"></a>
### `api.proposals.draft(action, options)`

Plan an edit once without applying it. The host retains the exact guarded operations for this actor and project. Requires read:project as well as an edit capability.

- **Permission:** propose:edits or write:edits
- **Parameters:**
  - `action` (string): transaction, annotate.apply, pour, route, fanout, autoplace, routePlan or planes.
  - `options` (object): Feature options, or {label, ops} for transaction. Ops use op add (doc, item), update (id, set), move (id, dx, dy), transform (id, set), remove (id), document (doc, set) or definition (def).
- **Returns:** `{handle, total, changes, ...report}` with at most 100 preview rows, or `{applied: 0}` for an unchanged design. A context holds up to 32 drafts and 8 Mi characters, evicting oldest first.

```js
const draft = await api.proposals.draft("annotate.apply", {action: "update"});
```

<a id="api-proposals-review"></a>
### `api.proposals.review(handle)`

Review one retained draft once. The editor always asks for an explicit selection, including for actors granted direct writes.

- **Permission:** propose:edits or write:edits
- **Parameters:**
  - `handle` (string): The handle returned to this context by proposals.draft.
- **Returns:** `{applied}` or zero with declined, stale, blocked, cancelled or revoked. A replaced project or changed planner input requires a fresh draft.

```js
if (draft.handle) await api.proposals.review(draft.handle);
```

<a id="api-proposals-discard"></a>
### `api.proposals.discard(handle)`

Release a retained draft belonging to this context.

- **Permission:** none
- **Parameters:**
  - `handle` (string): A handle returned by proposals.draft.
- **Returns:** True when the draft was present.

```js
await api.proposals.discard(draft.handle);
```

<a id="api-proposals-submit"></a>
### `api.proposals.submit(proposal, label)`

Submit an AtriumProposal v2 you built yourself, guarded by the values you read.

- **Permission:** propose:edits or write:edits
- **Parameters:**
  - `proposal` (object): `{format: "atrium-ai", version: 2, project: name, ops: [{op: "set", target: "item" | "document" | "project" | "library", document, id, path: [...], before, after} | {op: "add" | "remove", …}]}`. Omit `before` for a field that is absent; omit `after` to delete.
  - `label` (string): Undo label.
- **Returns:** `{applied}`, or `{applied: 0, declined: true}`.
- **Limit:** Operations per proposal: 500,000.

If any guarded value changed since you read it, the whole proposal is refused ("… has changed since this proposal was drafted"). Proposals can never write `extensions`, `scripts` or other code-bearing fields.

```js
const t = await api.items.get(id);
await api.proposals.submit({format: "atrium-ai", version: 2, project: (await api.project.info()).name,
  ops: [{op: "set", target: "item", document: t.document, id, path: ["width"], before: t.width, after: 0.4}]}, "Widen");
```

<a id="api-proposals-propose"></a>
### `api.proposals.propose(edits, options)`

Propose edits of whitelisted fields (see `proposals.fields`) for the user to review. The review shows each changed object as the visual diff does (Property, Before, After); the user picks the changes to apply, and they apply as one undo step. Nothing changes without that approval, even with `write:edits`.

- **Permission:** propose:edits or write:edits
- **Parameters:**
  - `edits` (object[]): `[{target: "item", id, path: ["sim", …], value} | {target: "definition", id, path, value} | {target: "project", path: ["simulation", "benches"], value}]`. `value` `null` deletes the field. Paths name plain object fields; one edit per field.
  - `options` (object): `{label}`: the review title and undo label.
- **Returns:** `{applied}`, `{applied: 0, declined: true}`, `{applied: 0, unchanged: true}`; without a host that can ask (headless, scripts) `{applied: 0, proposal}`.
- **Limit:** Proposed edits: 5,000 per proposal, paths up to 6 fields deep, 4 MB per value and 12 MB in all.

The current values become the proposal's guards. If any chosen field changes while the dialog is open, Waffle refuses the chosen edits together. The whole project is checked by the model validator before the user sees it. A proposal the user discarded is final: proposing the same edits again fails with "You already declined this change" and shows no dialog.

```js
await api.proposals.propose([
  {target: "item", id: part.id, path: ["sim"], value: {model: "D1N4148"}},
  {target: "project", path: ["simulation", "benches"], value: benches}], {label: "Save test bench"});
```


<a id="api-simulation-channel"></a>
### `api.simulation.channel(net, options)`

The routed copper of one board net, with what a transmission-line model needs: tracks (layer, width, points), vias (span, drill, land, back-drill and the stub lengths from the via-stub report), the pads of every component on the net (with all their pins, so series parts can be followed), the stack-up (each copper layer's depth and its cross-section: microstrip or stripline, dielectric heights, εr, tan δ, copper and cover thickness), the cross-section of each impedance profile a Width rule gives the net's tracks (its reference planes, etch factor and coplanar ground gap, as DRC and the Layer Stack Manager solve it) and, on request, other nets' tracks nearby. Read-only.

- **Permission:** read:project
- **Parameters:**
  - `net` (string): Net name.
  - `options` (object): `{doc, neighbours}`: `neighbours` (mm, at most 5) also returns other nets' tracks on the same layer within that distance.
- **Returns:** `{net, doc, stackup: {thickness, er, derived, layers: [{key, name, type, z, t, geometry}], profiles: {[profile]: {[layer]: geometry}}}, tracks: [{id, layer, width, points, profile}], vias: [{id, x, y, drill, diameter, from, to, backdrill, stub: {top, bottom, residual, used, status}}], pads: [{part, ref, pin, name, x, y, w, h, layer}], parts: [{id, ref, value, def, defName, parameters, pins}], neighbours: [{net, id, layer, width, points}], neighboursTruncated, clearance}` (`neighboursTruncated` is true when the neighbour search hit its work limit on a very large net)
- **Limit:** Objects per read: 20,000; page with `limit` and `offset`, or narrow the filter.

```js
const ch = await api.simulation.channel("DQ0", {neighbours: 0.5});
console.log(ch.tracks.length + " tracks, " + ch.vias.length + " vias");
```

<a id="api-simulation-fieldsolve"></a>
### `api.simulation.fieldSolve(geometry, options)`

Waffle's 2D quasi-static field solver for one transmission-line cross-section (single or coupled), run in the editor's solver worker. Results are cached by geometry; a caller may queue up to 8 solves.

- **Permission:** read:project
- **Parameters:**
  - `geometry` (object): Field-solver geometry in mm: `{structure: "microstrip" | "stripline" | "coupled-microstrip" | "coupled-stripline" | "cpwg" | …, w, s, h | h1, h2, t, er, tanD, cover: {t, er}, etch, g, rough}` (`etch`: trapezoid etch factor; `g`: coplanar ground gap; `rough`: rms copper roughness). `simulation.channel` gives each layer's `geometry`, and `stackup.profiles[track.profile][layer]` for a track under an impedance profile; add `w` (and `s` for a pair).
  - `options` (object): `{quality: "fast" | "normal", fGHz}`: `fGHz` adds conductor and dielectric loss at that frequency.
- **Returns:** `{ok, error, z0, z, zodd, zeven, zdiff, eeff, eeffOdd, eeffEven, delay (ps/mm), kb, kf, alpha_c, alpha_d (dB/mm), ms, warnings}`

```js
const r = await api.simulation.fieldSolve({...layer.geometry, w: 0.2}, {fGHz: 1});
console.log(r.z0.toFixed(1) + " Ω, " + r.delay.toFixed(2) + " ps/mm");
```

## Globals in the worker

| Global | Permission | |
| --- | --- | --- |
| `fetch(url, {method, headers, body, signal})` | network:<host> | Present only while at least one `network:` permission is turned on. The editor makes the request after checking the live grant on every call, with `redirect: "error"`, `credentials: "omit"`, `cache: "no-store"` and no referrer. `https://<host>` only (`network:localhost`: http or https to this computer, any port). Returns a standard `Response` whose body streams. Network: 8 open responses per extension. Network response: 64 MB per response. |
| `console.log / info / warn / error / debug` | none | Goes to the extension's log: Tools › Extensions › Output, and the developer Console. Log lines: 50 per second; the rest of that second is dropped. |
| `require("./file.js")` | none | CommonJS `require` for `.js` and `.json` files inside your own package. |
| `setTimeout / setInterval / clearTimeout` | none | Timers. Work outside a running command counts against the background CPU budget. Background CPU: 5 s of processor time per 10 s outside a running command, and a heartbeat every 1 s (silence for 20 s stops the worker). |

There is no `document`, `window`, `localStorage`, `indexedDB`, `importScripts`, `XMLHttpRequest`, `WebSocket` or editor global: the worker runs in a sandboxed iframe with the CSP `default-src 'none'`.
